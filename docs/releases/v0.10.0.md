# ccswarm v0.10.0

This release prevents invalid Sangha approval votes and repairs the release
distribution path. It also defines the future Sangha-centered product design.

## Fixes

- A failed reviewer cannot contribute an approval vote, even if its output
  ends with `SANGHA_DECISION=APPROVE`. Only completed reviews count; other
  execution results abstain and retain their original status in the report.
- A Sangha quorum larger than the effective member count fails validation
  before execution. This also covers the default three-member configuration.
- Generated member-name suffixes remain unique, so colliding names do not
  cause one review result to overwrite another.
- Updated `h2` to 0.4.16 for RUSTSEC-2026-0258 and applied compatible dependency
  fixes identified by the release audit.
- Linux builds use Rustls instead of requiring an OpenSSL development package.
- Publishing uses the current single `ccswarm` crate; obsolete `ai-session`
  publishing steps have been removed.

## Distribution

Linux and macOS archives are built and smoke-tested on native AMD64 and ARM64
runners. All four archives, SHA-256 checksums, and validation jobs must succeed
before publication. The workflow verifies downloaded draft assets, generates
build-provenance attestations, publishes the stable crate, then publishes the
GitHub release. Manual workflow runs perform validation without publishing.

## Usage

```bash
cargo install ccswarm --version 0.10.0 --locked
ccswarm --version
ccswarm flow check default
ccswarm pipeline --provider codex --model-override gpt-6-astra \
  --task "Review the proposed change" --dry-run
```

The preview does not launch a provider. Removing `--dry-run` starts the selected
flow, which may edit the workspace; model access depends on the Codex account.

## Compatibility And Limits

Existing valid flow YAML and the default two-of-three approval rule remain
supported. Configurations with an impossible quorum now fail early. Approval
text from unsuccessful execution no longer advances a Sangha stage.

Sangha does not yet resolve blocking objections or bind machine checks to a
reviewed revision. Sangha dispatch bypasses ordinary stage gates, and the Codex
adapter does not enforce read-only review. Workflow checkpoint resume and
Astra-specific steering, async tools, and native delegation remain future work.

The existing YAML dependencies retain the RustSec warnings
[RUSTSEC-2025-0067](https://rustsec.org/advisories/RUSTSEC-2025-0067) and
[RUSTSEC-2025-0068](https://rustsec.org/advisories/RUSTSEC-2025-0068).
Replacing that dependency chain remains separate work.

The [Sangha design](https://github.com/nwiizo/ccswarm/blob/v0.10.0/docs/SANGHA_PRODUCT_CORE.md) and
[Astra integration plan](https://github.com/nwiizo/ccswarm/blob/v0.10.0/docs/ASTRA_INTEGRATION.md) distinguish these future
capabilities from the current runtime.

To return to the previous CLI version, install `ccswarm` version `0.9.2` with
`cargo install ccswarm --version 0.9.2 --locked --force`. This does not undo
repository changes made by a workflow. This release introduces no checkpoint
or stored-state schema migration.
