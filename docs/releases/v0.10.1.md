# ccswarm v0.10.1

This patch applies the lessons from generating a working Order Desk app with
ccswarm and Codex. The previous example tested a saved app after a prompt
preview; it did not verify that a live provider produced a usable app.

The included HTML, CSS, and JavaScript were generated by the published
v0.10.0 `quick` flow using Codex CLI 0.153.4 with `gpt-6-astra`. That run
completed successfully, and the resulting app passed the maintained five
browser tests and ten logic tests. Browser validation is now owned by the
external harness, so generators do not need to discover browser tooling.

## Changes

- `examples/e2e-playwright/run.sh --live` generates into a fresh run directory
  and tests that exact app in Chromium. Missing output fails the run; the
  checked-in example is never used as a fallback.
- Every run retains its generated files, pipeline result, provider events,
  and preview. The default invocation clearly identifies its preview-only mode
  and tests the included app without calling a provider.
- The included Order Desk supports adding work, stage advancement, partial
  recovery, retry, deletion, and browser-local persistence, including an empty
  saved list. User-entered titles remain literal text.
- Browser tests exercise those actions, blank validation, and a mobile-width
  viewport. They now gate CI and release publication alongside the Rust checks
  and four-platform distribution checks.

## Try It

```bash
cargo install ccswarm --version 0.10.1 --locked
```

Open the included
[Order Desk HTML](https://github.com/nwiizo/ccswarm/blob/v0.10.1/examples/e2e-playwright/generated/index.html)
from a local checkout, with its neighboring CSS and JavaScript files.
The [example guide](https://github.com/nwiizo/ccswarm/blob/v0.10.1/examples/e2e-playwright/README.md)
explains browser setup and fresh generation through an authenticated Codex or
Claude Code CLI. Live runs consume provider usage.

## Scope And Limits

Order Desk is a local task-management demo. Its Sangha and recovery stages do
not invoke AI or demonstrate workflow checkpoint resume. Data stays in the
current browser; there is no server or multi-user synchronization.
The regenerated example uses a new storage key and does not import previous
demo orders. Old data is left untouched and remains readable by the v0.10.0
app at the same file location and browser profile; retain that copy if needed.

This patch does not change the workflow engine or provider adapter. The
Sangha gate/read-only limitations, planned Astra extensions, and existing
`libyml`/`serde_yml` RustSec warnings documented in
[v0.10.0](https://github.com/nwiizo/ccswarm/releases/tag/v0.10.0) remain.
