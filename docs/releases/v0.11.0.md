# ccswarm v0.11.0

This release makes [Herdr](https://herdr.dev) the terminal surface for local
provider execution. Every Claude or Codex call that ccswarm starts on your
machine runs in a background tab of the Herdr workspace you launched it from,
so stages, Sangha members, and parallel workers stay visible and stoppable.
The [Herdr Integration](../HERDR_INTEGRATION.md) document records the
researched Herdr 0.9.5 behavior and the design decisions.

## Changes

- **Herdr-required local execution.** Run ccswarm from a Herdr pane. Outside
  Herdr, the first provider call stops before retrying and explains how to
  continue. Remote A2A execution (`CCSWARM_A2A_ENDPOINT`) and commands that do
  not run providers do not need Herdr.
- **Headless stages (default).** `claude -p` and `codex exec` run in a new
  background tab through a short `/bin/sh` script. Output, exit codes, Claude
  stream-json telemetry, and Codex thread IDs come back through private files,
  unchanged from v0.10. The tab closes when the stage ends or is cancelled.
- **Live Claude stages.** `execution: live` starts an interactive Claude Code
  session with `herdr agent start`, submits the stage prompt, and reads the
  reply and token usage from the session transcript. You can watch, answer,
  or steer the session in its tab. When Claude asks a question, including
  folder trust for a repository it has not opened, ccswarm notifies you and
  waits; ccswarm never answers those questions itself.
- **Herdr state and notifications.** Headless stages report `working` with
  `$stage` and `$provider` sidebar tokens. Runs notify when they finish, when
  `auto --require-approval` waits, and when a live stage needs input; delivery
  follows your Herdr `ui.toast.delivery` setting.
- **Herdr plugin.** `herdr plugin install nwiizo/ccswarm/herdr-plugin --ref v0.11.0`
  adds run board, recent runs, and doctor actions.
- **Diagnostics.** `ccswarm doctor` checks the Herdr CLI, whether ccswarm runs
  inside Herdr, the server, and Herdr's Claude/Codex integrations.
- **Clean Ctrl-C.** Pressing Ctrl-C (SIGINT) during a run closes the stage's
  Herdr tab, which stops its provider, removes the temporary run directory,
  records an interrupted `task_end` event in `events.ndjson`, and exits with
  status 130.
- **Read-only Codex stages.** Codex stages with `permission: readonly`,
  including Sangha members, run with `codex exec --sandbox read-only` instead
  of `workspace-write`, even when their `tools:` list write or exec tools.
  If such a stage hits a rate limit and `on_rate_limit` points to a provider
  that cannot enforce read-only access, such as Claude, the stage fails
  instead of continuing with write access. The AI rule judge also runs
  read-only. Commands that write, such as builds and test runs, fail in a
  read-only Codex stage; run them as stage `gates:` instead. See
  [Stage Permissions](../APPLICATION_SPEC.md#stage-permissions).

## Removals

This release removes code and documents that the CLI never reached or that
no longer worked, about 10,000 lines in total:

- Library modules without CLI callers (`governance`, `hooks`, `identity`,
  `resource`, agent orchestration and type-state builders, session
  management, `utils` helpers, A2A Agent Card types).
- Bridge context history, session persistence, multi-turn continuation, and
  provider resume flags, which no flow could enable.
- The `ccswarm task` command (use `ccswarm queue`), `ccswarm doctor --error`,
  the unimplemented Linear tracker, pipeline config
  fields without setters, and harness fields that were parsed but ignored.
- The obsolete `sample/` scripts, `.ccswarm/pieces/`, and superseded research
  documents.

The bundled harness scenarios now use `flow:` and load again.

## Compatibility

- Local provider runs now require Herdr 0.9.5 or later.
- `session::execution::CommandExecution` exposes `exit_code` and `success()`
  instead of `ExitStatus`; `run_provider_command` takes a `HerdrCall`.
- Providers run with the Herdr pane's environment plus explicit command
  changes, rather than inheriting the ccswarm process environment.
- Flow YAML gains the optional stage field `execution` (`headless` by
  default). Existing flows run headless.
- Library consumers lose the removed modules above. The `task` command and
  `doctor --error` are gone; other CLI commands are unchanged.
- The lockfile updates `quinn-proto`, `rustls`, `rustls-webpki`, and
  `webpki-roots` to patch releases that fix the RustSec advisories reported
  against the previous versions; the dependency feature set is unchanged.

## Install

```bash
cargo install ccswarm --version 0.11.0 --locked
```

Linux and macOS archives are provided for AMD64 and ARM64, with SHA-256
checksums and GitHub build provenance.

## Scope And Limits

- Live stages support Claude only and run a single turn. Codex live sessions
  wait for Herdr to report Codex thread IDs reliably.
- Live sessions report token usage but not cost.
- Headless and live Claude stages still run with
  `--dangerously-skip-permissions`; read-only review is enforced only on
  Codex stages.
- Herdr-managed worktrees, socket event subscriptions, and remote Herdr
  machines are not used yet.
- Sangha decision behavior and the other
  [documented runtime limitations](https://github.com/nwiizo/ccswarm/blob/v0.11.0/docs/ROADMAP.md#known-runtime-limitations)
  are unchanged.
