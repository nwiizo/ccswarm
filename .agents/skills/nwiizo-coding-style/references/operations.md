# 操作ごとの手順

依頼された操作の部分だけを使う。`review`、`audit`、`debt`、`gain`、`help` は
現在の継続モードを変えない。`off` でも明示された操作だけは実行する。

## review: 差分レビュー

指定された対象を読む。対象がなければ、Git の staged / unstaged の差分と
untracked の新規ファイルを確認する。新規ファイルは `git diff` に出ないため実物を読む。

```bash
rtk git status --short
rtk git diff
rtk git diff --cached
rtk proxy git ls-files --others --exclude-standard
```

呼び出し元、周辺実装、検証を読み、次の観点で保守負担を減らせる箇所を探す。

| 種別 | 探すもの |
|---|---|
| `delete` | 未使用と確認できたコード、不要な設定、依頼に含まれない将来機能 |
| `reuse` | 同じ責務を実装し直している処理、既存の関数や型に統合できる重複 |
| `stdlib` | 標準ライブラリの具体的な機能で置換できる手書き処理 |
| `native` | ブラウザー、OS、データベースなどの標準機能で置換できる処理や依存 |
| `yagni` | 現在の用途や境界では必要性を説明できない抽象化、ラッパー、拡張点 |
| `shrink` | 同じ動作をより明瞭かつ小さく書ける処理 |

Rust では [rust-analysis.md](rust-analysis.md) の両CLIによる診断を加える。
指摘は場所、種別、不要と判断できる根拠、具体的な代替案、維持すべき動作を示す。
一つの実装や呼び出し元しかないことだけで抽象化を不要とは判断しない。

複雑さに集中したレビューであり、正しさ・安全性・性能を網羅したとは報告しない。
ただし、削除・置換案が入力検証やエラー処理を失わせないかは確認する。
範囲外の明白な不具合を見つけた場合は、その事実と未検証の範囲を伝える。

削減可能な行数や依存数を出す場合は、具体的な差分または置換案から数え、見込みと
実際の変更を区別する。根拠がなければ数値を出さない。指摘がなければその旨を返す。
レビューのみなら指摘で終え、修正も依頼されていれば適用と検証まで行う。

## audit: 全体監査

対象は指定されたリポジトリかディレクトリ。省略時は現在のリポジトリを使う。
管理対象のソースと依存定義を調べ、生成物、外部依存のコピー、ビルド出力を除く。
大きい対象は構造を把握してから領域ごとに読み、調べた範囲と未確認の範囲を報告する。

`review` と同じ観点を使い、既存の依存、通過するだけのラッパー、不要な設定、
重複責務、標準機能の再実装を探す。Rust では両CLIを使い、実際の解析範囲を
確認して重複実行を避ける。
保守負担と変更の確かさから優先順を付ける。推測の削減行数だけでは順位を決めない。
監査のみなら指摘で終え、改善の実行も依頼されていれば指定範囲で適用・検証する。

## debt: 残した制限の一覧

コードに残した次のコメントを検索する。`ponytail:` は既存資産との互換のために含める。

```bash
rtk proxy rg -n --hidden --glob '!.git/**' --glob '!node_modules/**' --glob '!vendor/**' --glob '!target/**' --glob '!dist/**' --glob '!build/**' '(nwiizo-coding-style|ponytail):' <対象>
```

ヒットの周辺を読み、実際のソースコメントだけを抽出する。説明文や文字列中の例は
集計しない。検索の終了コード1は該当なし、2は実行失敗として扱う。
言語固有のコメントやリポジトリの除外設定も考慮する。

ファイル・行、残した制限、見直す条件、対応をファイルごとに一覧化する。
見直す条件が書かれていないものには `no-trigger` を付け、推測で補わない。
最後に実際の件数と `no-trigger` の件数を示す。必要なら `git blame` で変更者を
調べられるが、変更者を今の担当者とは決めつけない。

保存も依頼されていれば指定先かリポジトリの既存の課題管理文書に書く。
明示された保存依頼にもう一度承認を求めない。報告だけの依頼ではファイルを増やさない。

## gain: 効果表示

公開ベンチマークのスコアを、対象モデル、課題数、反復回数、測定日と一緒に表示する。
起点は [2026-06-18 の公開結果](https://github.com/DietrichGebert/ponytail/blob/356918eba965ee1eac64bd3a7f0dd02108350de5/benchmarks/results/2026-06-18-agentic.md)。
その後の結果を求められた場合は、上流の新しい一次資料を確認する。

| Haiku 4.5・12機能課題・各4回、スキルなしとの比較 | 公開値 |
|---|---:|
| 差分の追加行数 | −54% |
| トークン数 | −22% |
| 費用 | −20% |
| 所要時間 | −27% |

これはPonytailの作者による測定であり、`nwiizo-coding-style` や現在のリポジトリの
効果ではない。旧版の単発応答での「80–94%削減」と混ぜない。
機能課題ではブラウザー・サーバーを動かしておらず、安全性は別の限定された検査。
結果を一般的な安全性の保証として表示しない。

手元の効果を求められた場合は、指定された変更前後で確認できる差分、依存数、
診断結果を示す。実測していないトークン・費用・速度や、作らなかったコードの量は
推定しない。コードが小さくなったことだけで動作の同等性を判断しない。
表や短い棒グラフは比較を助ける場合に使い、状態やモードは変更しない。

## help: 使い方

現在モードと既定値を確認し、`SKILL.md` の操作表に沿って説明する。
必要な操作が分かっていれば、その呼び出し例だけを示す。

```text
$nwiizo-coding-style full この処理を実装して
$nwiizo-coding-style review
$nwiizo-coding-style audit crates/parser
$nwiizo-coding-style debt
$nwiizo-coding-style gain
$nwiizo-coding-style default lite
$nwiizo-coding-style off
```

これはスキルの会話上の操作であり、同名のシェルコマンドではない。
モードは会話内で引き継ぎ、新しい会話では環境変数または文書の既定値に戻る。
開始時や子エージェント起動時の外部フックが動作しているとは説明しない。
